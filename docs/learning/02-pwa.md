# 학습 02. PWA는 무엇이고, 우리는 무엇을 설정했나

> 순서: ① 무엇인가 → ② 없으면 무슨 문제 → ③ 우리 프로젝트의 어디에 있나 → 확인 질문

---

## 1. PWA란?

**PWA(Progressive Web App) = 설치할 수 있는 웹사이트.**

일반 웹사이트와 똑같이 HTML, CSS, JS로 만든다. 여기에 **딱 두 가지 파일**을 더하면 브라우저가 "이건 앱처럼 설치할 수 있겠다"고 인정해 준다.

| 추가 파일 | 역할 | 비유 |
|---|---|---|
| **Web App Manifest** (`manifest.webmanifest`) | 앱 이름, 아이콘, 색, 여는 방식을 적은 JSON 파일 | 앱의 **신분증** |
| **Service Worker** (`sw.js`) | 브라우저와 서버 사이에서 요청을 가로채, 저장해 둔 파일을 대신 내주는 JS | 앱의 **비서** (주인이 없어도 대신 응대) |

그리고 조건이 하나 더 있다. **HTTPS**로 서비스해야 한다. 단, 개발용 `localhost`는 예외다.
Service Worker는 모든 요청을 가로챌 수 있는 강력한 권한이 있어서, 중간에 누가 내용을 바꿔치기할 수 없는 HTTPS에서만 허용된다.

### "Progressive(점진적)"의 의미
모든 브라우저에서 일단 **일반 웹사이트로 동작**하고, 지원하는 브라우저에서는 **설치, 오프라인 같은 기능이 추가로 켜진다.** 못 쓰는 환경에서도 망가지지 않고 기능이 점점 더해진다는 뜻이다.

## 2. Manifest: 앱의 신분증

**① 무엇인가**: 브라우저에게 "설치하면 이렇게 보여 달라"고 알려 주는 설정 파일.

**② 없으면?**: 홈 화면에 추가해도 주소창이 붙은 웹페이지 바로가기일 뿐이다. 아이콘도 사이트 스크린샷 같은 것으로 대충 만들어진다.

**③ 우리 프로젝트에서**: `vite.config.ts`의 `manifest: { ... }`에 적으면, 빌드할 때 `dist/manifest.webmanifest`로 만들어지고 `index.html`에 `<link rel="manifest">`가 자동으로 들어간다.

| 항목 | 우리 값 | 의미 |
|---|---|---|
| `name` / `short_name` | 여행 플랫폼 / 여행 | 설치 화면 이름 / 홈 화면 아이콘 아래 이름 |
| `display` | `standalone` | **주소창 없이** 앱처럼 연다. PWA를 앱처럼 느끼게 하는 핵심 |
| `start_url` | `/` | 아이콘을 누르면 여는 주소. 나중에 "열자마자 오늘 동선"(D-1)이 이 주소에서 시작한다 |
| `theme_color` | 파란색 | 상단 상태 표시줄 색 |
| `background_color` | 연회색 | 앱이 켜지는 순간의 스플래시 화면 배경 |
| `icons` | 64, 192, 512, maskable | 기기마다 필요한 크기가 달라 여러 개를 준다 |

## 3. Service Worker: 앱의 비서

**① 무엇인가**
웹페이지와 **별도로 백그라운드에서 동작하는 JS**다. 페이지가 서버에 파일을 요청하면 Service Worker가 먼저 받아서 판단한다.

```
[페이지] ──"index.html 주세요"──► [Service Worker] ──► 폰에 저장해 둔 게 있나?
                                       │   있음 → 바로 꺼내 줌 (인터넷 불필요, 매우 빠름)
                                       │   없음 → 서버에 요청해서 가져옴
```

처음 방문할 때 앱 파일 전체를 폰의 **Cache Storage**에 미리 저장해 둔다. 이것을 **precache**라고 한다.

**② 없으면?**
- 인터넷이 끊기면 "인터넷에 연결되어 있지 않습니다" 공룡 화면이 뜬다.
- 앱을 열 때마다 서버에서 파일을 새로 받아서 느리다.
- 여행 중 해외 로밍이나 지하철에서 일정을 못 본다. **우리 요구사항 D-1, D-2와 정면으로 충돌한다.**

**③ 우리 프로젝트에서**
- Service Worker 코드를 **직접 쓰지 않았다.** `vite-plugin-pwa`가 내부의 **Workbox**(구글이 만든 Service Worker 도구)로 `dist/sw.js`를 자동 생성한다.
- `workbox.globPatterns`: 어떤 파일을 미리 저장할지 정한다. 기본값은 js, css, html뿐이라 아이콘(png, svg, ico)을 추가했다.
- `registerType: 'autoUpdate'`: 새 버전을 배포하면 자동으로 교체하고 새로고침한다.
  - **버린 대안**: `'prompt'` ("새 버전이 있어요, 새로고침할까요?"라고 묻는 방식). 지금은 입력 화면이 없어서 묻지 않는 쪽이 단순하다. 일정 입력 폼이 생기면 작성 중 내용이 날아갈 수 있으므로 그때 `prompt`로 바꾼다.

**왜 직접 안 쓰고 플러그인을 쓰나?**
Service Worker를 직접 쓰면 "빌드할 때마다 바뀌는 파일 이름(`index-C-nd0UK4.js`처럼 해시가 붙음)을 목록에 넣고, 옛 버전 캐시는 지우고…"를 손으로 관리해야 한다. 틀리면 **사용자가 영원히 옛 버전을 보는** 치명적인 버그가 생긴다. 이 부분은 검증된 도구에 맡기는 게 맞다고 판단했다.

> ⚠️ 개발 서버(`npm run dev`)에서는 Service Worker를 끄는 것이 기본이다. 켜 두면 코드를 고쳐도 캐시된 옛 화면이 보여 헷갈리기 때문이다. 그래서 PWA 확인은 `npm run build` 후 `npm run preview`로 한다.

## 4. 아이콘

**① 무엇인가**: 홈 화면, 설치 화면, 앱 전환 화면에 쓰이는 이미지. 기기마다 요구하는 크기와 형식이 다르다.

| 파일 | 누가 쓰나 |
|---|---|
| `pwa-192x192.png`, `pwa-512x512.png` | 안드로이드 홈 화면, 설치 화면 (필수 크기) |
| `maskable-icon-512x512.png` | 안드로이드가 **원, 둥근 사각형 등 기기 모양대로 잘라** 쓰는 아이콘. 잘려도 그림이 안 잘리게 가운데에 여백을 둔다 |
| `apple-touch-icon-180x180.png` | **아이폰** 홈 화면. iOS는 manifest 아이콘 대신 `index.html`의 `<link rel="apple-touch-icon">`을 본다 |
| `favicon.ico`, `favicon.svg` | 브라우저 탭 아이콘 |

**③ 우리 프로젝트에서**
- 원본은 `public/favicon.svg` **하나**다. (기존 Vite 로고를 위치 핀 + 점선 동선 그림으로 교체)
- `pwa-assets.config.ts` + `npm run generate-pwa-assets` 명령으로 위 PNG를 전부 자동 생성한다.
  - **버린 대안**: 이미지 편집기로 크기별로 하나씩 만들기. 원본을 바꿀 때마다 다시 해야 한다.
- maskable과 apple 아이콘의 여백을 **흰색 대신 파란색**으로 채웠다. 흰색이면 폰이 동그랗게 잘랐을 때 파란 사각형 주변에 흰 테두리가 보이기 때문이다.

## 5. 직접 확인한 것

1. `npm run build` → `dist/`에 `manifest.webmanifest`, `sw.js`, 아이콘들이 생겼다.
2. `npm run preview`로 열고 Service Worker가 `activated` 상태이고, Cache Storage에 파일 12개가 저장된 것을 확인했다.
3. **서버를 끄고 새로고침해도 화면이 그대로 떴다.** Service Worker가 캐시에서 대신 내준 것이다. → 오프라인 동작 확인.

본인도 직접 해 볼 수 있다. 크롬에서 `npm run preview` 주소를 열고 `F12` → **Application** 탭에서 다음을 본다.
- **Manifest**: 이름, 아이콘, 색이 보인다
- **Service workers**: `activated and is running`
- **Cache storage**: 저장된 파일 목록
- **Service workers** 화면의 `Offline` 체크 → 새로고침해도 화면이 뜬다

## 6. PWA의 한계 (앞서 설계에서 정리한 것과 연결)
- 홈 화면 **위젯은 불가** → 8단계(Capacitor 앱 전환)에서 네이티브로 만든다.
- 아이폰은 사파리 "공유 → 홈 화면에 추가"를 **사용자가 직접** 해야 한다. 설치 버튼을 자동으로 띄울 수 없다.
- 지금 캐시되는 건 **앱 화면(코드)뿐**이다. 일정 **데이터**의 오프라인 저장은 4단계(오늘 화면)에서 따로 다룬다.

## 확인 질문

1. 웹사이트를 PWA로 만들려면 무엇 두 가지와 어떤 조건이 필요한가?
2. Service Worker는 어떻게 인터넷 없이도 앱을 열리게 하나?
3. `display: 'standalone'`을 빼면 무엇이 달라지나?
4. 왜 `npm run dev`가 아니라 `npm run preview`에서 PWA를 확인하나?
5. maskable 아이콘은 무엇이고, 왜 여백을 파란색으로 채웠나?
6. `registerType`을 지금은 `autoUpdate`로 했는데, 나중에 `prompt`로 바꾸려는 이유는?

## 내 답 (직접 작성)

1. Manifest, Service Worker, HTTPS
2. precache
3. 앱처럼 안 보이고 그냥 웹으로 열림
4. npm run dev는 코드를 바꾸면 바로 보이는데 npm run preview는 예전 버전을 보여주기 때문
5. 파란 사각형 주변에 흰 테두리를 보여주기 위함
6. 작성 중 내용이 날라갈 수 있기 때문

## 검토 (Claude)

1. **정답.** 덧붙이면 HTTPS 조건에서 개발용 `localhost`는 예외다.
2. **키워드만 맞음.** "precache"는 이름이고, 질문은 **어떻게**였다. 흐름으로 설명해야 한다.
   → 처음 방문할 때 Service Worker가 앱 파일(html, js, css, 아이콘)을 폰의 **Cache Storage에 미리 저장**(precache)해 둔다. 그 뒤로 페이지가 파일을 요청하면 Service Worker가 **중간에서 가로채** 서버 대신 캐시에서 꺼내 준다. 그래서 인터넷이 없어도 열린다.
3. **정답.** 더 구체적으로는 "주소창과 브라우저 메뉴가 붙은 웹페이지 바로가기처럼 열린다"이다.
4. **틀림 (원인을 반대로 이해함).** preview가 예전 버전을 보여주는 게 아니다.
   → **Service Worker는 `npm run build` 할 때만 만들어진다.** `npm run dev`에서는 일부러 꺼 둔다. 켜 두면 코드를 고쳐도 캐시된 옛 화면이 보여서 개발이 헷갈리기 때문이다. `npm run preview`는 **빌드 결과물(`dist/`)을 실제 배포처럼 띄워 주는** 명령이라 Service Worker까지 포함된 진짜 PWA를 확인할 수 있다.
5. **틀림 (반대로 이해함).** 흰 테두리는 **보이지 않게 하려고** 파란색으로 채운 것이다.
   → maskable 아이콘은 안드로이드가 **기기 모양(원, 둥근 사각형 등)대로 잘라** 쓰는 아이콘이다. 잘려도 그림이 남도록 가장자리에 여백을 둔다. 그 여백이 흰색이면 잘린 아이콘 테두리에 흰 띠가 보이므로, 배경과 같은 파란색으로 채워 자연스럽게 만들었다.
6. **정답.** 비교까지 하면 완벽하다. `autoUpdate`는 새 버전을 받으면 **묻지 않고** 새로고침하고, `prompt`는 사용자에게 **새로고침할지 묻는다.** 입력 폼이 생기면 묻는 쪽이 안전하다.

→ 4번과 5번은 다시 읽어 보고 내 말로 고쳐 써 보기.
