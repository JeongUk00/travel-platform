# 학습 03. 배포와 Vercel

> 순서: ① 무엇인가 → ② 없으면 무슨 문제 → ③ 우리 프로젝트의 어디에 있나 → 확인 질문

배포 주소: https://travel-platform-sigma.vercel.app/

---

## 1. 배포란?

**내 컴퓨터에서만 열리던 앱을, 인터넷의 누구나 열 수 있는 주소에 올리는 것.**

`npm run dev`의 `http://localhost:5173`은 **내 컴퓨터 안에서만** 열린다. `localhost`는 "이 컴퓨터 자신"이라는 뜻이기 때문이다. 여자친구 폰에서는 열 수 없다.
배포하면 `https://travel-platform-sigma.vercel.app`처럼 **어디서나 열리는 주소**가 생긴다.

## 2. 우리 앱은 "정적 사이트"다

`npm run build`의 결과물인 `dist/`는 **HTML, CSS, JS, 이미지 파일 묶음**일 뿐이다. 서버가 요청마다 무언가를 계산할 필요 없이 **파일을 그대로 건네주기만 하면** 된다. 이런 사이트를 **정적 사이트(static site)**라고 한다.
그래서 서버 컴퓨터를 빌려 24시간 켜 둘 필요 없이, 파일만 올려 두는 **무료 정적 호스팅**으로 충분하다.

> 데이터(로그인, 일정 저장)는 1단계부터 Supabase가 맡는다. 앱(파일)은 Vercel, 데이터는 Supabase로 역할이 나뉜다.

## 3. Vercel이 하는 일

```
git push ──► GitHub ──► Vercel이 변경 감지
                          1. 코드 가져오기 (git clone)
                          2. npm install
                          3. npm run build      ← 내 컴퓨터에서 하던 것과 같음
                          4. dist/를 전 세계 서버(CDN)에 복사
                          ▼
                 https://travel-platform-sigma.vercel.app (HTTPS 자동)
```

**① 무엇인가**: GitHub에 push하면 자동으로 빌드하고 배포해 주는 서비스.
- 이렇게 "코드를 올리면 자동으로 검사, 빌드, 배포"하는 흐름을 **CI/CD**(지속적 통합 / 지속적 배포)라고 한다.
- **CDN**(Content Delivery Network): 같은 파일을 세계 여러 지역 서버에 복사해 두고, 사용자와 가까운 서버에서 내준다. 일본 여행 중에 열어도 빠르다.

**② 없으면?**
- 매번 손으로 빌드하고, 서버에 파일을 올리고, HTTPS 인증서를 설정해야 한다.
- **PWA는 HTTPS가 필수**라서 인증서 없이는 설치도 오프라인도 안 된다. Vercel은 이걸 자동으로 해 준다.

**③ 우리 프로젝트에서**
- 별도 설정 파일 없이 Vercel이 `package.json`과 `vite.config.ts`를 보고 **Vite 프로젝트임을 자동 인식**했다.
  - Build Command: `npm run build` / Output Directory: `dist`
- `main` 브랜치에 push할 때마다 자동으로 재배포된다.

**버린 대안**: Netlify, Cloudflare Pages(거의 같은 기능, 무료), GitHub Pages(설정이 더 번거로움). Vite를 가장 손쉽게 자동 인식하는 Vercel을 골랐다.

## 4. 겪은 문제: 배포가 끝나지 않음

**증상**: 배포가 3분 넘게 "진행 중"이었고, 로그에 `Network: use --host to expose`가 떠 있었다.

**원인**: 이 문구는 **개발 서버(`npm run dev`)나 미리보기 서버(`npm run preview`)가 켜졌을 때** 나오는 메시지다. Build Command가 빌드가 아니라 서버를 켜는 명령으로 설정되어 있었던 것으로 보인다.
- **빌드**는 `dist/`를 만들고 **끝나는** 작업이다.
- **서버**는 요청을 기다리며 **끝나지 않는** 작업이다.
- Vercel은 빌드가 끝나기를 기다리는데 실행된 게 서버라서, 영원히 끝나지 않았다.

**해결**: Build Command를 `npm run build`로 바로잡고 다시 배포했다.

**교훈**: 로그의 한 줄로 "무엇이 실행됐는지"를 거꾸로 추적할 수 있다. 오류 메시지가 없어도 **평소와 다른 출력**이 단서가 된다.

> 재발 방지책(아직 안 함): 저장소에 `vercel.json`을 두고 빌드 명령을 코드로 고정하면, 웹 화면에서 설정을 잘못 바꿔도 저장소 값이 우선 적용된다. 이렇게 설정을 코드로 관리하는 방식을 **Configuration as Code**라고 한다.

## 5. 배포 후 확인한 것

| 확인 항목 | 결과 |
|---|---|
| 주소가 HTTPS인가 | ✅ `https:` |
| Service Worker 동작 | ✅ `activated` |
| manifest | ✅ 이름 "여행 플랫폼", `standalone` |
| 아이콘 5개 | ✅ 모두 200 (정상 응답) |
| `sw.js`의 캐시 설정 | ✅ `max-age=0, must-revalidate` |

**마지막 항목이 왜 중요한가?**
브라우저는 `sw.js`를 받아 두고 재사용할 수 있다. 만약 `sw.js` 자체가 오래 캐시되면 **새 버전을 배포해도 브라우저가 옛 `sw.js`를 계속 써서 업데이트를 영영 모르게 된다.**
`max-age=0, must-revalidate`는 "매번 서버에 새 버전이 있는지 확인하라"는 뜻이라 이 문제가 없다. Vercel의 기본값이 이미 안전하게 되어 있었다.

**안드로이드 (Chrome)**
1. 주소 열기 → 오른쪽 위 `⋮` → **홈 화면에 추가** 또는 **앱 설치**
2. 홈 화면의 파란 위치 핀 아이콘으로 실행 → 주소창 없이 열리면 성공

**아이폰 (Safari 필수, Chrome 앱에서는 설치가 제한될 수 있음)**
1. Safari로 주소 열기 → 아래쪽 **공유 버튼** (□↑) → **홈 화면에 추가**
2. 홈 화면 아이콘으로 실행 → 주소창 없이 열리면 성공

**오프라인 확인**: 한 번 연 뒤 비행기 모드를 켜고 아이콘으로 다시 열어 본다.

## 내 답 (직접 작성)

1. 본인 로컬 컴퓨터에서만 열리는 주소이기 때문
2. 파일만 주는 앱이였기 때문, 데이터는 supabase를 이용
3. vercel이 감지를 하고 clone을 하고 build를 하고 다시 배포를 함
4. npm run dev 또는 npm run preview를 했기 때문, 빌드는 돌리고 끝 서버는 계속 돌아감.
5. 업데이트시 반영이 안됨.
## 검토 (Claude)

1. **정답.** 더 정확히는 `localhost`가 "**지금 이 기기 자신**"을 뜻한다. 그래서 여자친구 폰에서 `localhost`를 열면 내 컴퓨터가 아니라 **여자친구 폰 자기 자신**을 찾는다.
2. **정답.**
3. **절반 정답.** 두 단계가 빠졌고, 마지막 단계가 모호하다.
   → push 감지 → clone → **`npm install`** → `npm run build` → **`dist/`를 CDN(전 세계 서버)에 올림.**
   install이 빠지면 build에 필요한 도구(Vite, TypeScript)가 없어서 빌드가 안 된다. "다시 배포"는 정확히 **빌드 결과물 `dist/`만** 올리는 것이다. 소스 코드 전체가 아니다.
4. **정답.** 다만 주어를 정확히 하면 "내가 dev를 실행한 것"이 아니라 "**Vercel의 Build Command가** 서버를 켜는 명령으로 설정되어 있었던 것"이다.
5. **결과만 맞음.** 면접에서는 **왜** 그렇게 되는지까지 말해야 한다.
   → 브라우저가 옛 `sw.js`를 캐시에서 계속 쓰면, 서버에 새 `sw.js`가 올라와도 **바뀐 것 자체를 모른다.** 새 버전을 받으러 가지 않으니 사용자는 **계속 옛 버전에 갇힌다.** 그래서 `sw.js`는 `max-age=0, must-revalidate`로 매번 서버에 확인해야 한다.
