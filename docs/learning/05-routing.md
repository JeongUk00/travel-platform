# 학습 05. 화면 이동(라우팅)과 React Router

> 순서: ① 무엇인가 → ② 없으면 무슨 문제 → ③ 우리 프로젝트의 어디에 있나 → 확인 질문

---

## 1. 라우팅이란?

**주소(URL)에 따라 어떤 화면을 보여줄지 정하는 것.**

| 주소 | 화면 |
|---|---|
| `/` | 여행 목록 |
| `/trips/osaka-2026` | 오사카 여행 상세 |
| `/login` | 로그인 |
| 그 외 | "페이지를 찾을 수 없어요" |

### 왜 화면마다 주소가 필요한가?
- **링크 공유**: "이 여행 봐" 하고 `/trips/osaka-2026` 주소를 카톡으로 보낼 수 있다. 요구사항 A-3(초대 링크)도 주소가 있어야 가능하다.
- **뒤로 가기**: 폰의 뒤로 가기 버튼이 앱 안에서 이전 화면으로 돌아간다.
- **새로고침해도 그 화면**: 상세 화면에서 새로고침해도 처음 화면으로 튕기지 않는다.

---

## 2. SPA: 페이지를 다시 받지 않는 웹앱

**옛날 방식 (MPA, Multi Page App)**: 링크를 누르면 서버가 **새 HTML 페이지를 통째로** 보낸다. 화면이 하얗게 깜빡이고, 앱이 기억하던 상태가 전부 사라진다.

**우리 방식 (SPA, Single Page App)**: HTML은 `index.html` **하나뿐**이다. 링크를 누르면
1. 브라우저 주소만 바꾸고 (서버에 요청 안 함)
2. React Router가 새 주소를 보고
3. 해당 화면 컴포넌트로 **그 자리에서 바꿔 그린다.**

→ 빠르고, 깜빡임이 없고, 앱처럼 느껴진다. PWA와 잘 맞는다.

**직접 확인한 것**: 메뉴를 세 번 눌러 화면을 옮기는 동안, 처음에 페이지에 붙여 둔 표시(`window.__marker`)가 계속 살아 있었다. 페이지를 다시 받았다면 사라졌을 것이다.

---

## 3. React Router

**① 무엇인가**: React에서 SPA 라우팅을 해 주는 라이브러리. 사실상 표준이다.

**② 없으면?**: 주소를 직접 읽어서 `if (주소 === '/login') ...`처럼 분기하고, 링크를 누를 때 주소를 바꾸는 코드, 뒤로 가기 처리까지 전부 직접 짜야 한다.

**③ 우리 프로젝트에서**

| 파일 | 역할 |
|---|---|
| `src/app/router.tsx` | **앱의 지도.** 주소 ↔ 화면 목록을 한곳에 모아 둔다 |
| `src/app/RootLayout.tsx` | 모든 화면이 공유하는 바깥 틀. `<Outlet />` 자리에 자식 화면이 들어간다 |
| `src/app/NotFoundPage.tsx` | 없는 주소일 때 (`path: '*'`) |
| `src/features/*/pages/*Page.tsx` | 각 화면. 지금은 자리만 잡은 빈 화면 |
| `src/main.tsx` | `<App />` 대신 `<RouterProvider router={router} />`를 그린다 |
| ~~`src/App.tsx`~~ | 역할이 router와 페이지들로 나뉘어서 **삭제** |

### 핵심 개념 4가지

**1) 중첩 라우트와 `<Outlet />`**
```
RootLayout (메뉴 + 바깥 틀)       ← 주소가 바뀌어도 그대로
  └─ <Outlet />                  ← 이 자리만 바뀜
       /          → TripListPage
       /login     → LoginPage
```
나중에 하단 탭바 같은 공통 메뉴를 한 번만 만들면 모든 화면에 붙는다.

**2) 동적 세그먼트 `:tripId`**
`trips/:tripId` 하나로 `/trips/abc`, `/trips/osaka-2026` 같은 모든 여행 주소를 처리한다. 화면 안에서 `useParams()`로 값을 꺼낸다. 2단계에서는 이 값으로 Supabase에서 그 여행을 불러온다.

**3) `<a href>` 대신 `<Link>` / `<NavLink>`**
`<a>`는 서버에서 페이지를 통째로 다시 받는다. SPA의 장점이 사라진다. `<Link>`는 주소만 바꾸고 React가 화면을 바꾼다. `<NavLink>`는 거기에 "지금 이 주소인가?"(`isActive`)를 알려 줘서 현재 메뉴를 굵게 표시할 수 있다.

**4) `createBrowserRouter` (객체 방식)**
- **버린 대안**: `<BrowserRouter><Routes><Route/></Routes></BrowserRouter>`처럼 JSX로 적는 방식.
- 둘 다 되지만, 객체 방식은 라우트 목록이 **데이터**라서 한눈에 보이고, 나중에 "로그인 안 했으면 `/login`으로 보내기" 같은 공통 처리를 붙이기 쉽다.

### 폴더 규칙 추가: `pages/`
설계 문서의 기능별 폴더 안에 `pages/`를 두었다.
- `pages/`: **주소 하나에 대응하는 화면 단위** (`TripListPage`)
- `components/`: 화면 안의 작은 조각 (나중에 `TripCard` 등)

## 4. 배포 사이트의 함정: 주소로 직접 들어가면 404

**문제**: SPA는 `index.html` 하나뿐이다. 그런데 누군가 공유받은 `https://.../trips/osaka-2026`를 **직접** 열면, Vercel은 `trips/osaka-2026`라는 **파일**을 찾는다. 그런 파일은 없으니 **404**가 뜬다.
(앱 안에서 링크로 이동할 때는 서버에 요청하지 않으므로 문제가 없다. 직접 열거나 새로고침할 때만 생긴다.)

**해결**: `vercel.json`
```json
"rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
```
"어떤 주소로 오든 `index.html`을 돌려줘라. 그러면 React Router가 주소를 보고 알맞은 화면을 그린다."
- `sw.js`, 아이콘, JS 파일처럼 **실제로 있는 파일**은 Vercel이 먼저 그 파일을 내주고, 없을 때만 이 규칙이 적용된다.
- 오프라인일 때는 Service Worker가 같은 역할을 한다. (캐시된 `index.html`을 내줌)

**같이 넣은 것**: `buildCommand`, `outputDirectory`, `framework`
첫 배포 때 Build Command가 잘못 잡혀 배포가 끝나지 않았던 문제(학습 노트 03)를 막기 위해, 빌드 설정을 **저장소에 코드로 고정**했다. 웹 화면에서 설정을 잘못 바꿔도 이 파일이 우선한다. (Configuration as Code)

> JSON 파일은 주석을 쓸 수 없어서 설명을 이 노트에 적었다.

## 5. 알아 둘 것: 번들 크기

라우터를 넣자 JS 파일이 약 69KB → **약 100KB**(gzip 기준)로 커졌다. 아직 문제될 크기는 아니다. 나중에 화면이 많아지면 "지금 보는 화면 코드만 먼저 받기"(코드 분할, lazy loading)를 검토한다.

## 확인 질문

1. 화면마다 주소(URL)가 있어야 하는 이유 2가지는?
2. SPA에서 링크를 누르면 무슨 일이 일어나나? `<a href>`를 쓰면 무엇이 달라지나?
3. `<Outlet />`은 무엇이고, 왜 쓰나?
4. `trips/:tripId`의 `:tripId`는 무슨 뜻이고, 화면에서 그 값을 어떻게 꺼내나?
5. `vercel.json`의 rewrites 규칙이 없으면 어떤 상황에서 404가 나나? 왜 그런가?

---

## 내 답 (직접 작성)

1. 링크 공유, 새로고침 해도 그 화면, 뒤로 가기
2. 브라우저 주소만 바꾸고, React Router가 새 주소를 보고, 해당 화면 컴포넌트로 그 자리에서 바꿔 그린다. 서버에서 페이지를 통쨰로 다시 받는다.
3. 중첩 라우트, 나중에 하단 탭바 같은 공통 메뉴를 한 번만 만들면 모든 화면에 붙는다.
4. 동적 세그먼트, useParams()로 꺼냄.
5. 파일이 없을 때, 파일이 없으니까..?
## 검토 (Claude)

1. **정답.** 세 가지 다 맞다.
2. **정답.** `<a href>` 쪽은 **결과**까지 말하면 좋다. 페이지를 통째로 다시 받으니 화면이 **깜빡이고**, 앱이 기억하던 **상태(입력 중인 내용 등)가 사라진다.**
3. **절반 정답.** "중첩 라우트"는 개념 이름이고, 질문은 `<Outlet />` **자체가 무엇인지**였다.
   → `<Outlet />`은 레이아웃 안에서 **"지금 주소에 맞는 자식 화면이 들어갈 자리"**다. 주소가 바뀌면 이 자리만 바뀌고 바깥 틀(메뉴)은 그대로 남는다. 쓰는 이유는 답에 쓴 대로, 공통 메뉴를 한 번만 만들면 되기 때문이다.
4. **절반 정답.** 이름과 꺼내는 방법은 맞다. **뜻**이 빠졌다.
   → `:tripId`는 "**이 자리에는 아무 값이나 올 수 있다**"는 표시다. 그래서 라우트 하나로 `/trips/abc`, `/trips/osaka-2026` 같은 **모든 여행 주소**를 처리한다. 여행마다 화면 파일을 만들 필요가 없다.
5. **방향은 맞지만 불확실함("..?").** 상황과 이유를 나눠서 정리해 보자.
   - **상황**: 배포 사이트에서 `/trips/osaka-2026`를 **주소창에 직접 입력하거나, 공유받은 링크로 열거나, 그 화면에서 새로고침할 때.** (앱 안에서 링크를 눌러 이동할 때는 서버에 묻지 않으므로 괜찮다.)
   - **이유**: SPA는 HTML 파일이 `index.html` **하나뿐**이다. 서버(Vercel)는 주소를 보고 `trips/osaka-2026`라는 **파일을 찾는데, 그런 파일은 없으니** 404를 낸다. `/trips/osaka-2026`는 파일이 아니라 **React Router만 아는 "가상 주소"**이기 때문이다.
   - **해결**: rewrites로 어떤 주소든 일단 `index.html`을 주면, 앱이 켜지면서 React Router가 주소를 읽고 알맞은 화면을 그린다.

→ 확신이 없을 때 "..?"로 남겨 둔 건 좋은 신호다. 모르는 부분을 숨기지 않고 표시해야 검토로 채울 수 있다.
